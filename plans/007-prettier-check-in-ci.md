## Why this matters

The code in this repo is consistently formatted today, but only because one person wrote it carefully by hand. Nothing checks it: CI runs the tests, the type check and the build, and no formatter or linter. As other lab members and coding agents contribute, style will drift and reviews will fill with whitespace noise. Adding Prettier in check mode to CI makes formatting automatic and keeps future diffs about content.

## Steps

### Step 1: Install and configure

```sh
npm install --save-dev prettier prettier-plugin-astro
```

Create `.prettierrc.json`:

```json
{
  "singleQuote": true,
  "printWidth": 120,
  "plugins": ["prettier-plugin-astro"],
  "overrides": [{ "files": "*.astro", "options": { "parser": "astro" } }]
}
```

Create `.prettierignore`:

```
# Content that lab members edit by hand on GitHub, generated data, and prose docs.
src/content/
src/data/
*.md
plans/
package-lock.json
dist/
.astro/
```

Add to `package.json` scripts, after the `"test"` line (add a comma to the `"test"` line):

```json
    "format": "prettier --write .",
    "format:check": "prettier --check ."
```

**Verify**: `npx prettier --version` prints 3.x; `npm audit` reports `found 0 vulnerabilities`.

### Step 2: Measure the reformat before applying it

```sh
npx prettier --check . ; npx prettier --list-different . | wc -l
```

Then, without committing, run `npx prettier --write .` and inspect `git diff --stat` and a sample of `git diff`.

Decide using this rule:

- If the diff is whitespace, quote-style and line-wrapping only, and under about 300 changed lines in total: good, continue.
- If many long lines are being re-wrapped, try `"printWidth": 125` and then `130`; keep the value that gives the smallest `git diff --shortstat`. Do not go above 130.
- If files under `src/content/`, `src/data/`, or any `.md` file appear in the diff: the ignore file is wrong. Fix `.prettierignore`.

Then undo the trial run: `git checkout -- . ':!package.json' ':!package-lock.json'` (keeps your step 1 edits to those two files; `.prettierrc.json` and `.prettierignore` are untracked and unaffected).

**Verify**: `git status --short` shows only `package.json`, `package-lock.json`, `.prettierrc.json`, `.prettierignore` (and the untracked `plans/` folder).

### Step 3: Wire it into CI and the README

In `.github/workflows/deploy.yml`, add one step between `- run: npx astro check` and `- run: npm run build`:

```yaml
      - run: npm run format:check
```

In `README.md`, add two rows to the commands table after the `npx astro check` row:

```markdown
| `npm run format` | Format the code with Prettier |
| `npm run format:check` | Check the formatting without changing files (also runs on every deploy) |
```

Commit this as commit 1. (`npm run format:check` fails at this commit; that is expected and is fixed by commit 2. Do not push between the two.)

### Step 4: Format, and prove nothing but formatting changed

```sh
npm run build && cp -R dist /tmp/dist-before
npm run format
npm run build
diff -r /tmp/dist-before dist && echo SAME-OUTPUT
```

**Verify**: prints `SAME-OUTPUT`. A difference limited to hashed file names under `dist/_astro/` for CSS or JS whose source whitespace changed is acceptable only if the corresponding HTML differs solely in those file names; any other difference is a STOP condition.

Then:

```sh
npm run format:check
npm test
npx astro check
git diff --stat -- src/content src/data '*.md'
```

Expected: `All matched files use Prettier code style!`; `pass 26`; 0 errors; and the last command prints nothing.

Commit as commit 2.

- The working tree is not clean when you start, or earlier plans are still in progress.
- `prettier-plugin-astro` fails to parse any `.astro` file, or its output changes rendered HTML (the `diff -r` in step 4 shows a real difference).
- The reformat touches more than about 300 lines even after tuning `printWidth` between 120 and 130. Report the numbers; the maintainer may prefer a different config.

- `npm install` reports a peer dependency conflict. Do not use `--force`.
